# falcon_work

Instrumentation, benchmarks and measurement records for **Falcon (FIPS 206 /
FN-DSA) signature generation on the CVA6 RISC-V core**.

This is the artifact for the ICCIT 2026 paper *"Cycle-Accurate
Characterisation of Falcon Signature Generation on the CVA6 Core"*. It contains
the instrumented Falcon trees, the benchmark harness, the two environment
patches and the measurement records behind the tables and figures.

---

## 1. What this repository is not

**It does not contain the build environment.** Running anything here needs a
CVA6 tree, a RISC-V toolchain, Verilator and a patched Spike, none of which are
version-controlled as a unit. The versions used are:

| Component | Version |
|---|---|
| Ubuntu | 24.04.4 LTS, under WSL2 |
| CVA6 | `openhwgroup/cva6` at commit `6cb2001`, plus `patches/cva6-6cb2001.patch` |
| Spike | 1.1.1-dev, plus `patches/spike-st_rvfi-speedup.patch` (roughly 5x faster) |
| Verilator | 5.050, **not** CVA6's pinned 5.008 |
| Toolchain | GCC 13.1.0, prefix `riscv-none-elf-` |

The scripts assume `$HOME/cva6` and `$HOME/falcon-work`. Clone this repository
to `$HOME/falcon-work` or the paths will not resolve.

Compiled binaries are deliberately not tracked. `.gitignore` was generated by
running `file(1)` over every file and excluding what reports as ELF, so
rebuilding is expected, not a sign something is missing.

## 2. Layout

| Path | What it is |
|---|---|
| `run_bench.sh` | The benchmark driver. Compiles and runs on Spike or the Verilator RTL model. See §3. |
| `progress.sh` | Live progress of a running RTL simulation. See §4. |
| `falcon_prof/` | Instrumented Falcon tree, software floating-point path (FPEMU). Fifteen segment boundaries. |

| `falcon/` | Uninstrumented working copy, for baseline timing. |
| `prof/` | The profiler core: `falcon_prof.c/.h`, `patch_prof.py`, and the precomputed keypairs for both parameter sets. |
| `host/` | Host-side key generation (`gen_key.c`), used to precompute keypairs. |
| `native_validate/` | Host-side validation that FPEMU and FPNATIVE produce byte-identical signatures. |
| `test/` | Small smoke tests for bring-up (`hello_rate.c`, `quiet.c`). |
| `collab_1024/` | Falcon-1024 cross-check bundle, with `ENVIRONMENT.txt` and `SHA256SUMS`. |
| `patches/` | The two out-of-tree patches the environment needs. See §6. |
| `reference/` | Pristine `Falcon-impl-20211101` plus the upstream zip, for diffing against. |
| `*.txt`, `*.log`, `variance.csv` | **Measurement records.** See §5. |

## 3. Running a benchmark

```
./run_bench.sh <mode> [bench]
```

**Modes**

| Mode | What it does |
|---|---|
| `spike` | Compile and run on Spike with no commit trace. Fast, small log. Use for correctness and instruction counts. |
| `rtl` | Run on the Verilator model via `cva6.py`. This is the only mode that gives true cycles. |
| `spike-trace` | Spike via `cva6.py` with the commit trace, needed by `profile_csv.py`. Produces roughly 100 bytes of log per instruction, so gigabytes for a full signature. Use sparingly. |

**Bench argument:** `sign` (default, keypair precomputed) or `full` (runs
keygen). Keygen takes about 86 ms on a host but did not finish in 40 minutes on
Spike, and it uses a different, coarser sampler that does not exercise
`SamplerZ`. Use `sign` unless you specifically want keygen.

**Environment variables**

| Variable | Values | Default |
|---|---|---|
| `TARGET` | `cv32a60x`, `cv64a6_imafdc_sv39` | **none, required** |
| `FP` | `emu`, `native` | `emu` |
| `LOGN` | `9` (Falcon-512), `10` (Falcon-1024) | `9` |

**`TARGET` has no default and the script refuses to run without it.** That is
deliberate. `cv64a6_imafdc_sv39` is the primary target and carries every
headline result; `cv32a60x` is the robustness check for datapath width. A
silent default would measure the wrong core for hours, which is the same trap
CVA6's own `Makefile:103` sets. `FP=native` is additionally rejected on
`cv32a60x`, which has `RVF=0, RVD=0` and therefore no FPU.

**Examples**

```bash
# Falcon-512, 64-bit core, hardware floating point, true cycles
TARGET=cv64a6_imafdc_sv39 FP=native ./run_bench.sh rtl

# the same build under software emulation, for the FP-mode comparison
TARGET=cv64a6_imafdc_sv39 FP=emu ./run_bench.sh rtl

# Falcon-1024 instruction counts, fast
TARGET=cv64a6_imafdc_sv39 FP=native LOGN=10 ./run_bench.sh spike
```

The ISA and ABI strings are copied from `cva6.py`'s own target table so the
compile matches what the RTL model was built for. Do not hand-edit them.

## 4. Watching an RTL run

RTL runs take hours. `run_bench.sh rtl` should be detached, and progress read
separately:

```bash
./progress.sh              # assumes 47,000,000 expected cycles
./progress.sh 95000000     # Falcon-1024, or any other expectation
```

It reads the live cycle counter out of `~/cva6/verif/sim/trace_hart_0.dasm`,
falling back to file size if the last line is mid-write. It is safe to run at
any time, including when nothing is running, in which case it reports the most
recent results files instead.

## 5. Measurement records: do not overwrite

The tracked `.txt`, `.log` and `.csv` files at the top level and in
`collab_1024/` are the **raw data behind a submitted paper**. They are results,
not build output.

| File | Contents |
|---|---|
| `rtl_prof_cv64a6_imafdc_sv39_{emu,native}.txt` | Per-segment RTL cycles, Falcon-512 |
| `rtl_prof_cv64a6_imafdc_sv39_{emu,native}_n1024.txt` | The same, Falcon-1024 |
| `rtl_prof_results.txt` | Collected summary |
| `last_spike_run_*.log` | Matching Spike instruction counts, used for the CPI figures |
| `variance.csv` | Stochastic sensitivity over 200 signatures |

`run_bench.sh` writes to these names. Before re-running a configuration that
already has a record, either commit first or move the old file aside. A
regenerated number that disagrees with the paper is a finding worth keeping,
not a file worth losing.

## 6. The patches

```bash
cd ~/cva6                     && git apply ~/falcon-work/patches/cva6-6cb2001.patch
cd ~/cva6/verif/core-v-verif  && git apply ~/falcon-work/patches/spike-st_rvfi-speedup.patch
```

`spike-st_rvfi-speedup.patch` is 7 insertions and 6 deletions, and it is worth
roughly a 5x speedup on Spike. `st_rvfi` is 192 KB and was being passed by
value once per simulated instruction.

Rebuild Spike after applying, and rebuild the Verilator model after applying
the CVA6 patch.

## 7. Conventions

Learned the expensive way.

- **Never mix an `-O3` timing run with a `-fno-inline` attribution run**, or
  their percentages. `BerExp` is `static` and inlines away at `-O3`.
- **Subtract counter overhead on RTL runs**, roughly 18 cycles per call.
  `SamplerZ` runs about 1000 times per signature. Accumulate into statics and
  report once; never print per call.
- **Verilator builds use `-Wno-fatal`.** Only errors stop a build.
- **Always pass `target=` explicitly** to CVA6's Makefile. `Makefile:103` claims
  the default is `cv32a60x`; the line below it sets `cv64a6_imafdc_sv39`.
- The toolchain triple is `riscv-none-elf`, not `riscv32-unknown-elf`.
- `profile_csv.py` counts instructions, not cycles. Cross-check only.
- Keygen is precomputed and reported separately.

## 8. Notes

The default branch is `main`.

Several `falcon_key.h` files contain precomputed Falcon keypairs. These are
benchmark keys, generated solely so that signing can be measured without
running key generation, and they protect nothing. Do not reuse them.
